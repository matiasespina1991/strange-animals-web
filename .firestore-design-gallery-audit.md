# Firestore design gallery implementation audit

## Existing client data paths

- `users/{browserId}`: identity font preferences; get/set, restricted by the existing identity account rules.
- `users/{browserId}/fontSets/{setId}`: identity font sets; collection read and set.
- `fonts/{fontId}` and `fonts/{fontId}/files/{fileId}`: full catalog and file manifests are readable by any authenticated account; catalog administration remains restricted to the fixed identity account.
- `images/{imageId}`: design configurator assets; list filtered by `assetType == "designConfigurator"` and get by document ID through the media repository.
- `sharedModels/{modelId}`: public GLB shares; create and get.
- `webampSkins/{skinId}`: list and get all documents, create and update.
- `tracks/{trackId}` and `siteContent/{sectionId}`: public media documents read by the media repository.

## Existing Firestore query filters

- `images`: `where("assetType", "==", "designConfigurator")`.
- `fonts`: no query filter; authenticated users can read disabled and enabled families and file manifests.
- No other `where`, `orderBy`, or `limit` calls were found in `src`.

## New private gallery data model

- `designUsers/{uid}/projects/{projectId}`: owner-scoped project metadata, latest sequential version number, and random latest-version UUID.
- `designUsers/{uid}/projects/{projectId}/versions/{versionId}`: immutable version metadata keyed by a random UUID, screenshot and design-storage paths, generated GLB path and timestamps.
- Large design JSON, front/back PNG captures, and generated GLB files belong in owner-scoped Cloud Storage paths, not Firestore documents.
- Gallery queries are limited to one user's nested projects, versions, and models, ordered by their timestamp/version fields.
- Storage paths include the owner UID, project UUID, and random version UUID, so simultaneous save attempts cannot upload to or clean up one another's paths.
- Firestore and Storage emulator tests verify authenticated font reads, owner-only gallery reads/uploads, cross-account denial, and immutable versions.
- Each Storage object is capped at 100 MiB. There is not yet a per-account project, version, or aggregate-storage quota; monitor usage and add quota enforcement if abuse or cost exposure becomes material.

## Authentication and database

- The design configurator is protected by the existing shared access-key session and keeps anonymous-session saves local. Gallery access and cloud saves use the separate `identity-account` Firebase Auth app with individual Google-authenticated UIDs.
- Existing `(default)` Firestore database is Standard edition in `europe-west3`.
- Firestore and Storage rules were compiled locally and deployed to `strange-animals-web`. No Hosting or Functions deployment was performed.
